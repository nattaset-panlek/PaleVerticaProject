# คู่มือการทำ Skill Visual และการส่งมอบงานสำหรับ VFX Artist (ภาษาไทย)

เอกสารฉบับนี้จัดทำขึ้นสำหรับทีมงานและผู้สร้างสรรค์เอฟเฟกต์ (VFX Artist) เพื่ออธิบายสถาปัตยกรรมและข้อกำหนดของระบบเอฟเฟกต์ (Skill Visual) ในเกม Realm of Hero เพื่อให้สามารถสร้างและตั้งค่าชิ้นงานให้ทำงานร่วมกับระบบเกมได้อย่างถูกต้องและสมบูรณ์

---

## 1. ภาพรวมระบบ (System Overview)

ระบบสกิลของ Realm of Hero ได้รับการออกแบบให้แยกส่วนกันอย่างชัดเจน (Decoupled) ตัว Effect Visual จะไม่มี Logic ในการคำนวณ Damage หรือ Logic การเล่นเกมใด ๆ ทั้งสิ้น โดยจะถูกสปอว์น (Spawn) ขึ้นมาตามความต้องการผ่านระบบ Skill Caster และควบคุมโดย `VisualManager` ร่วมกับ Component ช่วยเหลืออย่าง `SkillVisualEffect`

การส่งมอบงาน Visual Effect ให้ระบบสามารถทำงานได้:

* ต้องจัดเก็บเป็น **GameObject Prefab**
* ต้องแนบ Component **`SkillVisualEffect`** ไว้ที่ Root ของ Prefab (กรณีที่ต้องการให้สเกลตามพื้นที่อัตโนมัติ หรือให้ระบบลบวัตถุทิ้งหลังเล่นเสร็จ)
* ต้องตรงตาม **5 หมวดหมู่ Visual** ที่ระบบรองรับ

---

## 2. หมวดหมู่ Visual ทั้ง 5 แบบ (VisualCategory)

เมื่อตั้งค่า ActiveSkill ScriptableObject จะสามารถเลือก `VisualType` ได้ ซึ่งแต่ละประเภทจะมีพฤติกรรมการเกิดและการเคลื่อนไหวที่ระบบโปรแกรมไว้ ดังนี้:

### A. Instant Hit (InstantHit)

* **คืออะไร**: เอฟเฟกต์ที่แสดงผลทันทีบนตัวเป้าหมาย
* **การใช้งาน**: การโจมตีระยะประชิด (Melee strike), คำสาป (Curses), สเปลเป้าหมายเดี่ยว
* **พฤติกรรมในโค้ด**: สปอว์น `ImpactVfxPrefab` ที่ตำแหน่งของเป้าหมายแต่ละตัวโดยตรง
* **ข้อกำหนดทางศิลป์ (Art Guidelines)**:
  * Pivot (จุดหมุน) ของ Prefab (0,0,0) ควรอยู่ที่ตำแหน่งเท้าหรือตรงกลางตัวของเป้าหมาย ขึ้นอยู่กับประเภทเอฟเฟกต์
  * ต้องดูแลเรื่องการลบตัวเอง (Cleanup) หรือใช้ Component `SkillVisualEffect` ช่วยจัดการลบเอฟเฟกต์อัตโนมัติ

### B. Projectile (Projectile)

* **คืออะไร**: เอฟเฟกต์ประเภทกระสุนหรือวัตถุที่เคลื่อนที่ในแนวตรง
* **การใช้งาน**: ลูกธนู, บอลไฟ, ขวานขว้าง
* **พฤติกรรมในโค้ด**:
  * สปอว์น `ProjectilePrefab` ที่ตำแหน่งผู้ร่าย (`OriginPosition`)
  * หมุน Prefab ไปยังทิศทางเป้าหมายโดยอัตโนมัติ (โดยใช้มุมเอียง -90 องศาเพื่อจัดแนวตามทิศของ Unity 2D)
  * หากค่าจำนวนกระสุน (`ProjectileCount`) มากกว่า 1 ระบบจะคำนวณกระจายทิศทางเป็นรูปพัดโดยอัตโนมัติ (กระจายได้สูงสุด 180 องศา)
* **ข้อกำหนดสำคัญทางศิลป์ (Critical Art Guidelines)**:
  * **ทิศทางของ Sprite**: ตัว Sprite หรือ Particle ทิศทางมุ่งหน้าหลักใน Prefab **ต้องหันไปทางด้านบน (แกน Y+)** เสมอ เนื่องจากสมการหมุนในโค้ดอิงแกนนี้เป็นหลัก หากเอฟเฟกต์หันไปทางแกนขวา (X+) หรือซ้าย (X-) จะทำให้ทิศทางการบินเอียงผิดรูปทันทีเมื่อนำไปเล่นจริง
  * **การเคลื่อนที่**: ตัว Prefab กระสุนจะต้องมี Script เคลื่อนที่ของตัวเอง (เช่น เคลื่อนที่ไปข้างหน้าตามทิศทางแกน Y+ ใน Local Space) หรือใช้ Physics Controller

### C. Ray Beam (RayBeam)

* **คืออะไร**: ลำแสงเลเซอร์หรือเส้นพลังงานเชื่อมต่อระหว่างผู้ร่ายกับเป้าหมาย
* **การใช้งาน**: ลำแสงสายฟ้า, ลำแสงเลเซอร์, สกิลดูดพลังงานแบบต่อเนื่อง
* **พฤติกรรมในโค้ด**:
  * สปอว์น `BeamVfxPrefab` ที่ตำแหน่งผู้ร่าย (`OriginPosition`)
  * ค้นหา Component **`LineRenderer`** ใน Prefab
  * เซ็ตจุดเริ่มต้น (Index 0) ไปที่ตำแหน่งผู้ร่าย และจุดสิ้นสุด (Index 1) ไปที่ตำแหน่งเป้าหมายแต่ละรายโดยอัตโนมัติ
* **ข้อกำหนดสำคัญทางศิลป์ (Critical Art Guidelines)**:
  * ใน Prefab **ต้องมี** Component `LineRenderer` อยู่ที่ Root หรือใน Child เสมอ
  * ควรใช้ Shader แบบเลื่อน UV (Scrolling UV Textures) หรือ Shader ค่อยๆ จางลง เพื่อทำให้ลำแสงขยับเคลื่อนไหวได้สวยงาม

### D. Ground Eruption (GroundEruption)

* **คืออะไร**: สเปลพลังงานปะทุขึ้นจากพื้นหรือเอฟเฟกต์วงกว้างบนพื้นดิน
* **การใช้งาน**: อุกกาบาตตกกระทบพื้น, เสาไฟปะทุ, แผ่นดินไหว, เสาน้ำแข็งผุด
* **พฤติกรรมในโค้ด**:
  * สปอว์น `EruptionVfxPrefab` ที่ตำแหน่งเป้าหมาย (หรือตำแหน่งผู้ร่าย หากไม่ได้กำหนดเป้าหมายไว้)
  * หากสกิลนั้นมีค่ารัศมีระเบิด (AOE Radius) มากกว่า 0 ระบบจะปรับสเกลของ Transform Prefab ให้เท่ากับเส้นผ่านศูนย์กลางโดยอัตโนมัติ: `localScale = (AOERadius * 2, AOERadius * 2, 1)`
* **ข้อกำหนดสำคัญทางศิลป์ (Critical Art Guidelines)**:
  * **จุด Pivot ของ Prefab ต้องอยู่ที่กึ่งกลางด้านล่างสุด (Ground Level / ระดับพื้นดิน)** เพื่อให้เวลาปรับสเกลขนาดเอฟเฟกต์ไม่จมหรือลอยจากพื้นดิน
  * ส่วนประกอบย่อยทั้งหมด (Sprites, Particle Systems) ต้องรองรับการปรับสเกลตาม Parent

### E. Aura Buff (AuraBuff)

* **คืออะไร**: เอฟเฟกต์ต่อเนื่องที่ติดตัวตัวละครไปตลอดเวลา
* **การใช้งาน**: โล่บาเรีย, วงแหวนรักษาฟื้นฟูพลังชีวิต, เอฟเฟกต์เพิ่มพลังโจมตี
* **พฤติกรรมในโค้ด**:
  * สปอว์น `AuraVfxPrefab` ที่ตำแหน่งของเป้าหมาย
  * ผูก Prefab ให้อยู่ภายใต้ Parent Transform ของเป้าหมาย เพื่อให้เคลื่อนที่ตามตัวละครตลอดเวลา
* **ข้อกำหนดสำคัญทางศิลป์ (Critical Art Guidelines)**:
  * จุด Pivot ของ Prefab ต้องอยู่ที่พิกัด (0,0,0) (ตำแหน่งเท้าหรือหน้าอกของตัวละคร)
  * ตัวเอฟเฟกต์ควรทำงานแบบ Loop ได้อย่างราบรื่น เนื่องจากสกิลประเภทนี้มักเปิดทิ้งไว้เป็นเวลานาน

## 3. Component `SkillVisualEffect`

เพื่อให้ทำงานง่ายขึ้น ให้แอดสคริปต์ `SkillVisualEffect` ลงใน Root Prefab โดยจะช่วยจัดการฟีเจอร์ต่าง ๆ ดังนี้:

* **ปรับสเกลอัตโนมัติ (`autoScaleToAOE`)**:
  * เมื่อเปิดตัวเลือกนี้ ขนาด `localScale` ของ Prefab จะขยายเท่ากับขนาดรัศมีเส้นผ่านศูนย์กลาง AOE ของสกิลตอนสปอว์นโดยอัตโนมัติ
* **ลบตัวเองอัตโนมัติ (`destroyAfterDuration`)**:
  * เมื่อเปิดตัวเลือกนี้ ระบบจะคำนวณช่วงเวลาทำลายตัวเองทิ้ง
  * ในช่อง **`linkedParticles`** สามารถลาก Particle Systems ต่าง ๆ มาใส่ได้ ระบบจะเช็คเวลา Duration + Lifetime ที่นานที่สุดของพาร์ทิเคิลเหล่านั้น และจัดการทำลายทิ้งให้พอดีโดยที่เอฟเฟกต์ไม่โดนตัดฉับระหว่างเล่น
* **แอนิเมชันสำหรับร่ายเวทย์ (`SpriteRendererFillSkill`)**:
  * หากระบุ SpriteRenderer ในช่องนี้ ระบบจะใช้แสดงความคืบหน้าในการร่ายเวทย์
  * Sprite จะค่อย ๆ สเกลจากขนาด 0 ไปจนถึง `Vector3.one` ตามเวลาของการร่ายเวทย์ (Cast Time) เมื่อร่ายเสร็จสมบูรณ์ Sprite ตัวนี้จะถูกทำลายทิ้งไปเอง เพื่อปล่อยให้เอฟเฟกต์หลักเล่นต่อ

## 4. วงเล็งเป้าหมายสกิล (Skill Targeting Indicators)

ก่อนที่สกิลจะแสดงผลจริง ตัวละครผู้เล่นจะมีวงตัวอย่างเล็งทิศทาง โดยระบบ `SkillIndicatorManager` จะเรียกใช้ Templates ในระบบดังนี้:

### วงเล็งตอนเตรียมสกิล (Aiming Phase) เทียบกับ วงเล็งตอนร่ายสกิล (Casting Phase)

ระบบจะมีการสลับแสดงผลวงเล็งเป้าหมายแตกต่างกันตามสถานะการสั่งใช้งาน:

1. **ช่วงเตรียมสกิล (Aiming Phase - กด Shortcut เตรียมเล็ง)**:
   * ระบบจะแสดงผล **วงเล็งมาตรฐานของตัวเกม (Circle, Line, Cone)** เพื่อบอกระยะร่ายและทิศทาง โดยจะข้ามการเรียกใช้งาน `SkillIndicatorPrefab` ของตัวเองไปก่อนเพื่อให้วงเล็งในเกมมีความสอดคล้องเสมอกัน
2. **ช่วงร่ายเวทย์ (Casting Phase - คลิกซ้ายสั่งใช้งานสำเร็จและกำลังเก็บเกจร่าย)**:
   * วงเล็งเตรียมสกิลหลักจะถูกซ่อนตัวลงไป (หรือเปิดทิ้งไว้ตามประเภทของสกิลระบุทิศทาง)
   * ระบบจะสร้าง (Instantiate) วงเล็งพิเศษ **`SkillIndicatorPrefab`** ที่ระบุไว้ใน ActiveSkill ออกมา ณ จุดล็อกพิกัดบนพื้นดินโดยอัตโนมัติ
   * ระหว่างที่ร่ายเกจอยู่ ระบบจะส่งค่าความก้าวหน้าการร่าย (0.0 ถึง 1.0) ไปให้ฟังก์ชัน `SetProgress` ของ Prefab นี้โดยตรง เพื่อใช้อนิเมตพาร์ทิเคิลหรือความเข้มแสง
   * เมื่อร่ายเวทย์เสร็จสิ้น หรือถูกขัดจังหวะ วงเล็งพิเศษนี้จะถูกทำลายทิ้งไปเองโดยอัตโนมัติ

### รูปแบบมาตรฐาน (Default Indicators)

ขึ้นอยู่กับระบบเล็งเป้าหมาย (Targeting Logic) ของสกิลนั้น ๆ:

1. **CircleIndicator**: ใช้สำหรับเล็งพื้นหรือพื้นที่ทรงกลมรอบตัว แสดงวงขอบเขตระยะร่ายรอบตัว และวงกลมบอกขนาดพื้นที่สกิล (AOE) บนจุดเล็ง
2. **LineIndicator**: ใช้สำหรับเล็งโจมตีแนวตรงหรือพื้นที่สี่เหลี่ยมผืนผ้า แสดงขนาดความกว้างและความยาว มีการรับส่งค่า `_FillAmount` ไปที่ Shader เพื่อสร้างเอฟเฟกต์การชาร์จเกจเล็ง
3. **ConeIndicator**: ใช้สำหรับเล็งพื้นที่รูปกรวย แสดงรัศมีและมุมกรวย มีการอัปเดตมุมผ่านตัวแปร `_ConeAngle` และค่อย ๆ ขยายสเกลออกไปขณะร่าย

### โครงสร้าง Shader และ Material สำหรับเล็งเป้าหมาย

หากต้องการทำ Shader สำหรับแสดงผลวงเล็งเอง ต้องกำหนด Property ชื่อตรงกันดังนี้:

* **`_FillAmount`**: ค่า Float ทศนิยมจาก 0 ถึง 1 บอกความคืบหน้าของการชาร์จ/ร่ายสกิล
* **`_ConeAngle`**: ค่า Float กำหนดมุมองศาของเอฟเฟกต์รูปกรวย
* **`_HeadTex`**: Texture ส่วนหัวลูกศร / หัวระนาบนำทางของเส้นระบุทิศทาง

## 5. รายการตรวจสอบก่อนส่งงานสำหรับ Visual ซ่า (Handover Checklist)

เช็คหัวข้อเหล่านี้ทุกครั้งก่อนนำ Prefab ไปใส่ใน Skill ScriptableObject เพื่อลดโอกาสเกิดข้อผิดพลาด:

1. [ ] **จุดหมุน (Pivot Point)**: เช็คให้ดีว่า Pivot อยู่ที่ระดับพื้นพิกัด (0,0,0) (ยกเว้นเอฟเฟกต์ลอยฟ้าเฉพาะทาง)
2. [ ] **ทิศทางกระสุน (Projectile Orientation)**: ตรวจสอบความถูกต้องของ Sprite หรือทิศทาง Particle Velocity ใน Prefab ของกระสุนว่าหันตรงดิ่ง **ขึ้นด้านบน (แกน Y+)** เสมอ
3. [ ] **เส้นลำแสง (LineRenderer)**: หากเป็นหมวด RayBeam ต้องมี Component `LineRenderer` อยู่ใน Prefab แน่นอน
4. [ ] **ห้ามใส่ Gameplay Logic**: ตัว Prefab ต้องไม่มี Component เกี่ยวกับ Rigidbodies, Colliders หรือ Script คำนวณความเสียหายใด ๆ ทั้งสิ้น (ตัวโปรแกรมออกแบบให้คำนวณดาเมจผ่านโค้ดภายนอกอย่างอิสระ)
5. [ ] **ทำความสะอาดเอฟเฟกต์**: แอด Component `SkillVisualEffect` ที่ Root, ติ๊กถูกที่ `destroyAfterDuration` และลาก Particle Systems ไปใส่ใน `linkedParticles` เสมอ เพื่อให้ระบบลบขยะทิ้งอัตโนมัติ
