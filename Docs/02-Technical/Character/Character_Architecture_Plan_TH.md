# แผนสถาปัตยกรรมตัวละคร: "ร่างเดียว ผู้ควบคุมแยก" (Character + PlayerCore + AgentCore)

สถานะ: **C1–C7 ทำเสร็จแล้ว** (2026-10-16) รายละเอียดสิ่งที่ทำจริงอยู่ใน [Character_System.md](./Character_System.md)

สถานะเดิม: ร่างฉบับที่ 2
ฉบับนี้ปรับตามไอเดียล่าสุด: ใช้ชื่อ **PlayerCore** กับ **AgentCore**, และให้ **AgentCore มีตัวเดียวคุม AI ได้หลายตัวละคร**

---

## 1. เป้าหมาย (สิ่งที่อยากได้)

1. **ตัวละครในโลกเป็นแค่ "ร่าง" (`Character`)**: มีแค่ตัวมันเอง คือค่าพลัง การเคลื่อนที่ สกิล บัฟ และภาพ ไม่ประมวลผล input หรือ AI เอง แค่รับ "ค่าสุดท้าย" (คำสั่ง) แล้วทำตาม
2. **สร้างตัวละครจากข้อมูล แล้วลงทะเบียนด้วย ID**: spawn หรือ generate ตัวละครตามข้อมูลที่ระบุ ได้ ID ประจำตัว แล้วลงทะเบียนไว้ที่เดียว
3. **`PlayerCore` คุมทุกอย่างของผู้เล่น**: รับ input, ประมวลผล, ผูกกล้องกับตัวละคร, ผูก UI แล้วส่งแค่คำสั่งสุดท้ายเข้าไปที่ตัวละคร ไม่ไปยุ่งข้างในตัวละคร
4. **`AgentCore` มีตัวเดียว คุม AI ได้หลายตัวละคร**: ตัวละครที่สร้างเสร็จและลงทะเบียนแล้วจะถูกส่งให้ `AgentCore` ซึ่งสร้างโหนดและข้อมูล AI ให้ตัวละครนั้นตามข้อมูลที่ระบุไว้
5. **มีตัวกลาง (`ControlSystem`) ตัดสินสุดท้ายว่าใครควบคุมร่างไหน**: ทั้ง `PlayerCore` และ `AgentCore` ต้อง "ขอ" สิทธิ์ควบคุมจากตัวนี้ก่อน และระบบอื่น (สกิล เควสต์ เดฟ) ขอยึดชั่วคราวแล้วคืนได้
6. **แบ่งประเภทแค่สองแบบ: Player กับ Entity**: Entity คือร่างที่ `AgentCore` คุม จะเป็น monster ชาวบ้าน พ่อค้า หรือบอส ให้ระบุด้วยแท็กหรือโปรไฟล์ AI
7. **prefab ตัวละครตัวเดียว**: ปรับแต่งด้วยข้อมูลให้เป็นตัวละครอื่นได้
8. **อนาคต (ยังไม่ทำตอนนี้)**: `AgentCore` ปรับประสิทธิภาพตามระยะผู้เล่น เช่น แบ่ง chunk ตัวที่อยู่ไกลคิดช้าลงหรือหลับ แต่วางโครงไว้ให้ต่อยอดได้

## 2. ทำได้ไหม: ได้ และเป็นแนวมาตรฐาน

การมี "ตัวคุม AI ตัวเดียวสำหรับหลายร่าง" เป็นแบบที่เกมจำนวนมากใช้ (เรียกกันว่า AI Manager / AI Director / แนวคิดแบบ ECS)

| ข้อดี | เหตุผล |
|---|---|
| เร็วขึ้น | loop เดียวคิดให้ทุกตัว แทนที่จะมี `Update()` ของ AI กระจายอยู่ร้อยตัว |
| ทำ optimize ตามระยะได้ง่าย | เพราะ AgentCore เห็นทุกตัวในที่เดียว จะแบ่ง chunk, คิดทุกเฟรม / ทุก N เฟรม / หลับ ก็ทำที่เดียว |
| debug ง่าย | เปิดดูได้ที่เดียวว่าตอนนี้ AI ตัวไหนคิดอะไรอยู่ (หน้าต่าง Agent Monitor ที่มีอยู่แล้วต่อยอดได้เลย) |
| แยก "ตัวกำหนดพฤติกรรม" ออกจาก "ร่าง" ชัด | ร่างไม่มีโค้ด AI อยู่ข้างในเลย |

**สิ่งที่ต้องออกแบบให้ดี (ไม่ใช่ปัญหา แค่ต้องคิดไว้ก่อน):**
- **สถานะของแต่ละตัวต้องแยกเก็บต่อตัว** ห้ามเก็บไว้ในตัวแปรของ `AgentCore` เอง ใช้ `AgentHandle` ต่อตัวละคร (มี blackboard และโหนดของตัวเอง)
- **ลำดับชีวิต**: เกิด → ลงทะเบียน → ขอสิทธิ์ควบคุม → ตาย/หาย → คืนสิทธิ์ → ถอนทะเบียน ต้องครบทุกขั้น ไม่งั้นมีตัวค้าง
- **โค้ดที่ผูกกับ GameObject รายตัว** เช่น coroutine ท่าตาย หรือ animation event ต้องย้ายไปที่ร่าง (`CharacterPresenter`) ไม่ใช่อยู่ใน `AgentCore`

## 3. สภาพปัจจุบัน (จากการอ่านโค้ดจริง)

### 3.1 ประเภทตัวละครที่มีอยู่

| ประเภท | Class | อยู่ที่ไหน | ใครควบคุม | สิ่งที่มีเฉพาะตัว |
|---|---|---|---|---|
| ฐาน | `Character` (abstract, 459 บรรทัด) | ทุกตัว | — | ค่าพลัง, เคลื่อนที่, สกิล, อุปกรณ์, ชุด, passive, ตีธรรมดา, regen |
| ผู้เล่น | `PlayerCharacter` | **อยู่ใน scene `SandBox.unity` เท่านั้น ไม่มี prefab** | `PlayerController` (บังคับต้องคู่กับ `PlayerCharacter`) | Save/Load, ผูก `GameData.Player`, เมนู K, passive records, กล้องสั่น |
| ศัตรู | `EnemyCharacter` (31 บรรทัด) | `Dummy.prefab`, `Skeletom.prefab` | `AgentCore` (ตัวละครละ 1 ตัว) | กฎ hard-code อย่างเดียว: Dummy มี HP 9,999,999 |
| NPC | `NonPlayerCharacter` (108 บรรทัด) | `Ally.prefab` | `AgentCore` (บังคับต้องมี) | `npcId`, `interactable`, กระเป๋า, `CommandMoveTo` / `CommandFollow` |
| ไม่ได้ใช้ | `NPCBrain`, `NPCInventory`, `NPCRoutine` | ไม่มี prefab ไหนใช้ | — | ร่าง V2 ส่วนใหญ่ถูก comment |

### 3.2 โครงสร้าง GameObject ตอนนี้

```
ผู้เล่น (อยู่ใน scene)                    Entity (prefab: Dummy / Skeletom / Ally)
├─ PlayerCharacter  ← ร่าง + session      ├─ EnemyCharacter / NonPlayerCharacter ← ร่าง
├─ PlayerController ← input + animation   ├─ AgentCore (971 บรรทัด, ติดทุกตัว) ← AI + animation + หลอดเลือด + ตาย
├─ BuffSystem                             ├─ BuffSystem
├─ EntityVisualController                 ├─ EntityVisualController
└─ CharacterVisualController              └─ Model / BuffCanvas / Shadow (ทั้ง 3 prefab เหมือนกันทุกชิ้น)
```

**ข้อสังเกต:** ตอนนี้ `AgentCore` เป็น component ติดอยู่บนตัวละคร**ทุกตัว** (ตัวละครละ 1 อัน) แผนใหม่เปลี่ยนเป็น**ตัวเดียวทั้งเกม**

### 3.3 ปัญหาที่เจอ

| # | ปัญหา | ผลกระทบ |
|---|---|---|
| 1 | ประเภทร่างผูกตายกับคนควบคุม (`PlayerController` ↔ `PlayerCharacter`, `NonPlayerCharacter` ↔ `AgentCore`) | สลับคนควบคุมไม่ได้ ทำสกิลยึดร่างไม่ได้ |
| 2 | Enemy กับ NPC ต่างกันแค่ข้อมูล (ศัตรู/พวกตัดสินด้วย faction อยู่แล้ว) | subclass แทบว่าง มีแต่ hack HP ของ Dummy |
| 3 | animation / flip / ทิศหน้า / ท่าตาย เขียนซ้ำใน `PlayerController` และ `AgentCore` | แก้ที่หนึ่งแล้วอีกที่ไม่ตาม |
| 4 | `CommandDirector` มีแค่ 2 ระดับ ไม่มีลำดับ ไม่มีเวลา ไม่คืนเอง และ**ตีธรรมดาไม่ผ่านตัวนี้** | ยึดร่างแล้วยังโดนสั่งตีธรรมดาแทรกได้ |
| 5 | `PlayerCharacter` ปนร่างกับ session ผู้เล่น (Save/Load, เมนู K, GameData) | เปลี่ยนร่างไม่ได้ |
| 6 | `AgentCore` ทำทุกอย่างในไฟล์เดียว 971 บรรทัด และติดทุกตัว | ขยาย AI ยาก, optimize รวมไม่ได้ |
| 7 | prefab แยกต่อตัวละคร และผู้เล่นไม่มี prefab | สร้างตัวละครใหม่ต้องก๊อป prefab |
| 8 | ไม่มีทะเบียนตัวละครกลาง ไม่มี ID ตอนรัน | หาตัวละครด้วย ID ไม่ได้ ต้องใช้ Find หรือถือ reference ตรง |

## 4. ภาพเป้าหมาย

```
                      ┌──────────────────────┐        ┌────────────────────────────┐
  input / กล้อง / UI  │      PlayerCore      │        │   AgentCore (ตัวเดียว)       │
  ──────────────────► │  (คุมผู้เล่น 1 ร่าง)   │        │  AgentHandle #12 → โหนด/BB  │
                      │  Possess(runtimeId)  │        │  AgentHandle #13 → โหนด/BB  │
                      └──────────┬───────────┘        │  AgentHandle #14 → โหนด/BB  │
                                 │ ขอสิทธิ์ / ส่งคำสั่ง    └──────────────┬──────────────┘
                                 │                                    │ ขอสิทธิ์ / ส่งคำสั่ง
                                 ▼                                    ▼
          ┌──────────────── ControlSystem ของแต่ละร่าง (Core Logic ตัดสินสุดท้าย) ────────────────┐
          │  เลน: Dev 100 > ยึดร่าง 50 > สคริปต์ 30 > เจ้าของ 10 (PlayerCore หรือ AgentCore)          │
          │  สัญญาเช่า (lease): ใครถือ ลำดับเท่าไหร่ หมดเมื่อไหร่ แล้วคืนให้เจ้าของเดิมอัตโนมัติ            │
          └─────────────────────────────────────────┬────────────────────────────────────────────┘
                                                    ▼
             ┌──────────── Character (ร่าง, prefab เดียว, runtimeId = 12) ────────────┐
             │  ค่าพลัง · เคลื่อนที่ · สกิล · บัฟ · อุปกรณ์ · CharacterPresenter (ภาพ)   │
             │  ตัวตน: CharacterId (ชนิดในข้อมูล), RuntimeId (ตัวนี้), Faction, Tags     │
             └───────────────────────────────────────────────────────────────────────┘
                      ▲ ลงทะเบียนตอนเกิด / ถอนตอนหาย
             ┌────────┴─────────┐
             │ CharacterRegistry │  ← หาตัวละครด้วย RuntimeId ได้ทุกที่
             └──────────────────┘
```

### 4.1 ชิ้นส่วนและหน้าที่

| ชิ้นส่วน | หน้าที่ | มีกี่ตัว / อยู่ที่ไหน |
|---|---|---|
| **`Character` (ร่าง)** | class เดียว ไม่แยก Player/Enemy/NPC รับคำสั่งผ่าน `ControlSystem` แล้วทำตาม | 1 ต่อตัวละคร, `Character.prefab` ตัวเดียว |
| **`CharacterPresenter`** | animation, flip, ทิศหน้า, ท่าตาย ฟัง event ของร่าง (แทนโค้ดซ้ำตอนนี้) | component บนร่าง |
| **`ControlSystem`** (Core Logic) | ตัดสินว่าใครส่งคำสั่งได้ ด้วยเลน + ลำดับ + สัญญาเช่า ทุกคำสั่ง (เดิน ร่าย ตีธรรมดา โต้ตอบ) ต้องผ่าน และปฏิเสธได้ (เช่นบอสติดแท็ก `ImmuneToControl`) | 1 ต่อตัวละคร (อัปเกรดจาก `CommandDirector`) |
| **`CharacterRegistry`** | ทะเบียนกลาง: ตัวละครทุกตัวได้ `RuntimeId` ตอนเกิด และค้นหาได้ด้วย ID | static |
| **`CharacterFactory`** | `Spawn(characterId, ตำแหน่ง)`: สร้างร่างจาก prefab เดียว + ใส่ข้อมูล → สร้าง ID → ลงทะเบียน → ส่งต่อให้เจ้าของ (`AgentCore` หรือ `PlayerCore`) ตามข้อมูล | static, ทางเดียวในการสร้างตัวละคร |
| **`PlayerCore`** | คุมทุกอย่างของผู้เล่น: input, ประมวลผลการควบคุม, ผูกกล้อง, ผูก UI, Save/Load, เมนู K แล้วส่งแค่คำสั่งสุดท้ายให้ร่าง `Possess(runtimeId)` เพื่อเปลี่ยนร่างได้ | 1 ตัว, GameObject แยก `[Runtime] PlayerCore` |
| **`AgentCore`** | **ตัวเดียวทั้งเกม** คุม AI ทุกตัว: รับร่างที่ลงทะเบียนแล้ว สร้าง `AgentHandle` ต่อร่าง (โหนดและ blackboard ตามโปรไฟล์ AI) ขอสิทธิ์ควบคุม แล้วคิดและส่งคำสั่งทุกเฟรม | 1 ตัว, GameObject แยก `[Runtime] AgentCore` |
| **`AgentHandle`** | ข้อมูล AI ของร่างหนึ่งตัว: runtimeId, โปรไฟล์, โหนด, blackboard (เป้าหมาย สถานะ cooldown ฯลฯ), ระดับการคิด (ใช้ตอน optimize) | 1 ต่อร่างที่ AI คุม (plain C# อยู่ใน AgentCore) |
| **`AgentProfile`** | ข้อมูลว่าตัวละครนี้คิดแบบไหน: ชาวบ้าน, monster ก้าวร้าว, พ่อค้า, บอส + โหนดที่ใช้ + ค่าปรับ (ระยะมองเห็น ระยะหนี ฯลฯ) | ข้อมูล (ScriptableObject หรือ JSON) |

### 4.2 ลำดับการสร้างตัวละคร (Spawn → Register → Assign)

1. **Spawn**: `EntitySpawner` หรือเควสต์ หรือเดฟ เรียก `CharacterFactory.Spawn(characterId: 10, ตำแหน่ง)`
2. **Build**: factory สร้างร่างจาก `Character.prefab` แล้วใส่ข้อมูลของ characterId 10 (รูปร่าง, ค่าพลัง, faction, แท็ก, โปรไฟล์ AI)
3. **Register**: `CharacterRegistry` ให้ `RuntimeId` ใหม่ (เช่น 12) แล้วเก็บไว้
4. **Assign**: ดูข้อมูลว่าใครเป็นเจ้าของ
   - ถ้าเป็น AI → `AgentCore.Register(12, profile)` → AgentCore สร้าง `AgentHandle` แล้วขอสิทธิ์ "เจ้าของ ลำดับ 10" จาก `ControlSystem` ของร่าง 12
   - ถ้าเป็นผู้เล่น → `PlayerCore.Possess(12)` → ขอสิทธิ์ "เจ้าของ ลำดับ 10" แล้วผูกกล้องและ UI
5. **Run**: ทุกเฟรม `AgentCore` คิดให้ทุก `AgentHandle` แล้วส่งคำสั่งผ่าน `ControlSystem` ส่วน `PlayerCore` แปลง input เป็นคำสั่ง
6. **Despawn**: ตัวละครตายหรือหายไป → คืนสิทธิ์ → `AgentCore` ลบ handle → `CharacterRegistry` ถอนทะเบียน

### 4.3 การแบ่งประเภท (wording ใหม่)

- **Player** = ร่างที่ `PlayerCore` ถือสิทธิ์อยู่ (เป็นบทบาท ไม่ใช่ประเภทร่าง)
- **Entity** = ร่างที่ `AgentCore` ถือสิทธิ์อยู่
  - **ชาวบ้าน (Villager), monster, บอส, พ่อค้า** = แท็กหรือ `AgentProfile` ในข้อมูล
- **ศัตรูหรือพวก** ตัดสินด้วย faction เหมือนเดิม

### 4.4 ตัวอย่าง: สกิลยึดร่าง (แค่คอนเซ็ปต์)

1. ผู้เล่นใช้สกิลใส่มอนสเตอร์ RuntimeId 14 สกิลขอ `ControlSystem` ของร่าง 14: "ขอเช่าลำดับ 50 นาน 5 วินาที ผู้ถือคือ PlayerCore"
2. `ControlSystem` ตรวจกฎ: บอสติด `ImmuneToControl` → ปฏิเสธ, ไม่ใช่ → อนุมัติ
3. `AgentCore` เห็นว่า handle #14 เสียสิทธิ์ชั่วคราว จึงข้ามการคิดของตัวนี้
4. `PlayerCore` คุมร่าง 14 ได้ (กล้องจะย้ายตามหรือไม่ ขึ้นกับสกิล)
5. หมดเวลา → `ControlSystem` คืนสิทธิ์ให้ `AgentCore` เอง → handle #14 กลับมาคิดต่อ
6. เดฟ (ลำดับ 100) ยึดร่างไหนก็ได้ตลอดเวลา

### 4.5 การ optimize ในอนาคต (วางโครงไว้ ยังไม่ทำ)

`AgentHandle` มีค่า "ระดับการคิด" ไว้ตั้งแต่แรก แต่ phase แรกทุกตัวคิดทุกเฟรมเหมือนเดิม ภายหลังค่อยเพิ่ม:

| ระยะจากผู้เล่น | ระดับ | คิดบ่อยแค่ไหน |
|---|---|---|
| ใกล้ (อยู่ใน chunk เดียวกันหรือติดกัน) | Active | ทุกเฟรม |
| กลาง | Reduced | ทุก N เฟรม |
| ไกล | Sleep | ไม่คิด รอผู้เล่นเข้าใกล้ |

## 5. แผนงานแบ่ง Phase (ปรับใหม่)

| Phase | งาน | เปลี่ยน gameplay? | ความเสี่ยง |
|---|---|---|---|
| **C1** | แยก `CharacterPresenter` ออกจาก `PlayerController` และ `AgentCore` (animation, flip, ท่าตาย) | ไม่ | ต่ำ |
| **C2** | อัปเกรด `CommandDirector` เป็น `ControlSystem` (เลน, ลำดับ, สัญญาเช่า, คืนอัตโนมัติ) ให้ตีธรรมดาผ่านด้วย และเพิ่มเทส | ไม่ | ต่ำ |
| **C3** | `CharacterRegistry` + `RuntimeId` (ตัวละครทุกตัวลงทะเบียนตอนเกิด ถอนตอนหาย) | ไม่ | ต่ำ |
| **C4** | `PlayerCore`: ย้าย input, กล้อง, UI, Save/Load, เมนู K ออกจาก `PlayerController`/`PlayerCharacter` ไปไว้ใน GameObject แยก และใช้ `Possess(runtimeId)` | ไม่ | กลาง |
| **C5** | `AgentCore` ตัวเดียว: ย้ายตรรกะ AI เดิมทั้งก้อนจาก component รายตัวไปเป็น `AgentHandle` ใน AgentCore กลาง (พฤติกรรมเหมือนเดิมทุกอย่าง แค่เปลี่ยนที่อยู่) | ไม่ | กลาง ถึง สูง |
| **C6** | รวม `PlayerCharacter` / `EnemyCharacter` / `NonPlayerCharacter` เป็น `Character` + แท็ก, ย้ายกฎ HP ของ Dummy ไปไว้ในข้อมูล | เล็กน้อย (โครงสร้าง) | **สูง**: แก้ scene และ prefab ใน Unity |
| **C7** | `Character.prefab` ตัวเดียว + `CharacterFactory` (Spawn → Register → Assign) แล้วให้ `EntitySpawner` ใช้ factory | ไม่ | กลาง |
| **C8** | ระบบโหนด AI + `AgentProfile` แทนตรรกะก้อนเดิม (รวมไอเดีย `NPCBrain` V2) | ใช่ (AI ใหม่) | กลาง |
| **C9** | Optimize ตามระยะ / chunk ใน `AgentCore` | ไม่ (เร็วขึ้น) | กลาง |
| **C10** | ตัวอย่างสกิลยึดร่างตัวแรก และเลน dev ในเมนู K | ใช่ (ฟีเจอร์ใหม่) | ต่ำ |

**หลักการ:**
- C1 ถึง C5 ตัวเลขและพฤติกรรมในเกมไม่เปลี่ยน
- C6 และ C7 แตะ prefab, scene และระบบเซฟ: ต้องปิด Unity ตอนทำ และทดสอบใน Play mode ด้วยกันหลังจากนั้น
- ทุก phase compile + รันเทสใน Unity แล้ว commit แยก

## 6. ความเสี่ยงที่ต้องระวัง

| เรื่อง | ทำไมเสี่ยง | วิธีรับมือ |
|---|---|---|
| ชื่อ `AgentCore` ใช้ซ้ำแต่ความหมายเปลี่ยน (จากรายตัว เป็นตัวเดียวทั้งเกม) | prefab ทุกตัวมี component `AgentCore` ติดอยู่ ถ้าเปลี่ยน class เดิมตรงๆ prefab จะเพี้ยน | ระหว่าง C5 ให้ component รายตัวเดิมเปลี่ยนชื่อเป็นตัวชั่วคราว (เช่น `AgentLegacyLink`) ที่แค่ลงทะเบียนร่างเข้า AgentCore กลาง แล้วค่อยลบออกตอน C7 |
| ข้อมูลใน prefab ของ subclass (เช่น `npcId`) | ลบ subclass แล้วค่าที่เซฟไว้หาย | ย้ายค่าไปไว้ในข้อมูลก่อนลบ class |
| scene อ้างถึง component `PlayerCharacter` | ต้องแก้ใน Unity | ทำ C6 ตอนปิด Unity |
| ไฟล์เซฟเก่า | ย้าย Save/Load ไป `PlayerCore` แล้ว format ต้องเหมือนเดิม | คง `PlayerDataModel` เดิม และเพิ่มเทสโหลดเซฟ |
| prefab ผูก event ปุ่มด้วยชื่อ class | เปลี่ยนชื่อแล้วปุ่มหลุด (เจอมาแล้วใน N3) | อัปเดต `m_TargetAssemblyTypeName` ใน prefab ไปพร้อมกัน |
| งานที่คุณยังไม่ commit (`PlayerController.cs`, `PlayerCharacter.cs`) | C1 ถึง C6 แก้สองไฟล์นี้หนัก | **แนะนำให้ commit งานของคุณก่อนเริ่ม C1** |

## 7. สิ่งที่ต้องยืนยัน

| # | คำถาม | ข้อเสนอของผม |
|---|---|---|
| 1 | ใช้ชื่อ **`PlayerCore`** และ **`AgentCore`** (เพิ่มคำลงท้าย `Core` ลงในมาตรฐาน = "ตัวกลางตัวเดียวที่ขับหลายอย่างในโดเมนเดียว" เหมือน `CombatCore`) | ใช่ |
| 2 | `AgentCore` มีตัวเดียวทั้งเกม คุมทุก AI ผ่าน `AgentHandle` ต่อร่าง | ใช่ |
| 3 | ทุกตัวละครได้ `RuntimeId` จาก `CharacterRegistry` และสร้างผ่าน `CharacterFactory` ทางเดียว | ใช่ |
| 4 | ลำดับเลน: Dev 100 > ยึดร่าง 50 > สคริปต์ 30 > เจ้าของ 10 | ตามนี้ |
| 5 | ระบบโหนด AI (ตัดสินตอน C8) | Behavior Tree (นิยมสุด debug ง่าย) หรือ Utility AI (เหมาะกับชาวบ้านที่ใช้ชีวิตเอง) |
| 6 | เริ่มที่ C1 และ C2 ก่อน | ใช่ เพราะไม่เปลี่ยน gameplay และเสี่ยงต่ำ |

ถ้าส่วนไหนเข้าใจไม่ตรงกับที่คิดไว้ บอกได้เลย ผมจะแก้เอกสารก่อนลงมือทำ
