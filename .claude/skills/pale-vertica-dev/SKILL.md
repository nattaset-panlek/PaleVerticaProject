# Pale Vertica Dev Skill

Unity **6000.4.8f1**, URP 2D, Input System, Addressables, TMP, Newtonsoft JSON, DOTween, Hot Reload (Asset Store). All game code compiles into `Assembly-CSharp` (no asmdefs). Project name everywhere (menus, docs, Unity `productName`, folder): "Pale Vertica". It was called "Realm of Hero" / "Realm Hero" until 2026-10-17; archived docs (`Docs/99-Archive/`) and `Backup/` still use the old name.

## 1. Non-negotiable rules (from `AGENTS.md`)
- Reply in **English**, no emoji, concise. Show only modified blocks/methods with clear placement when presenting code to the user.
- **No code comments** unless asked.
- Every C# script uses the five regions in this order: `#region [Variables/Fields]`, `[Properties]`, `[Unity Methods]`, `[Public Methods]`, `[Private Methods]` (bracketed names). Keep them when editing older files that use unbracketed names.
- No god classes. Data in ScriptableObjects/JSON, communication via C# `event Action`.
- UI only **listens** to events. Never poll data in `Update()` when an event exists.
- **Do not change core formulas** (anything in `CoreSystem/Combat/Formulas/`: stat value, derived stats, damage, cast time, cooldown, cost, regen, ASPD, refine, EXP) without explicit user approval. Callers such as `Attribute`, `AttributeSystem`, `SkillInstance`, `SkillCaster`, `Character`, `Equipment` only gather inputs and apply results; never put arithmetic back into them.
- Docs go to `Docs/` only (see section 6). Never create `.md` under `Assets/`.
- **Player-facing text needs EN and TH** (AGENTS.md section 9): UI text through `LocalizationDatabase.Get(key)` / `LocalizedTextView` with the key in `Assets/Resources/Localization/Strings.json`, data text as `LocalizedString`. `LocalizationTests` fails on a missing language.

## 1b. Naming and references (full standard: `Docs/02-Technical/Coding_Standards.md`)
- **Suffix = script type.** `Manager` only for a single global instance per scene/session; `System` for a per-character subsystem; `Player*` for player state; `Controller`, `Director`, `View`/`Window`/`Modal`/`Slot` (UI that only listens), `Database`, `Loader`, `Storage`, `Formula`, `Registry`, `Events`, `Factory`; `Settings`/`Table`/`SO` for ScriptableObject data. No `Helper`/`Utils`. Do not invent new suffixes.
- **Runtime-created objects** (not in a prefab or scene): one `Create()`/`Factory` entry point, GameObject named `[Runtime] X` under the `[Runtime]` root, self-register in `Awake`/clear in `OnDestroy`, expose `IsReady`/`OnReady`, `[DisallowMultipleComponent]` + `[AddComponentMenu("")]`. Nothing uses `DontDestroyOnLoad`; session-long data is a plain C# singleton (`Database`).
- **No runtime Find** (`FindAnyObjectByType`, `FindObjectsByType`, `GameObject.Find`, `FindGameObjectWithTag`) in new game code: use serialized/hierarchy refs, self-registering `Manager`s, `Registry`, or `Events` (core raises, UI listens). Find is fine in `Editor/` and `Reset()`/`OnValidate()`. Existing Find calls are scheduled for removal after the rename phases.
- **Files and namespaces**: one public type per file, file name = type name (grouped enums/structs: `<Area>Types.cs`); namespace = folder path.
- **Renaming**: keep the `.meta` with MonoBehaviour/SO files; add `[MovedFrom]` for `[SerializeReference]` types (`EffectLogic`, `TargetingLogic`, `ActionRider` subclasses); never rename names used as strings (Workbench `SkillConverter`, JSON `EffectType`) without updating them; check `Resources`/Addressables paths before moving folders.
- Legacy names: none left from N1–N5. Multi-type files that had uncommitted user edits at migration time (`UIManager`, `UIElementRegistrySO`, `CursorManager`) still hold several types; split them when next touched.

## 3. Data sources of truth
- Gameplay numbers live in JSON: `Assets/Resources/Data/{Item, ItemSet, Faction, Attribute, Skill, SupportSkill, SkillTree, Character, UniquePassive}.json`. Edit them through **Window > Pale Vertica > Pale Vertica GameDataWorkbench**, not by hand when possible.
- Skill behaviour lives in `ActiveSkill` assets under `Assets/Resources/Skill/ActiveSkill`; `Database.GetSynchronizedSkill(id)` clones the asset and overwrites numbers from `Skill.json`.
- ID ranges and data conventions: `Docs/03-Project/Planning_Guide.md`.
- Save files: `persistentDataPath/Saves/save_slot_{n}.json` via static `SaveStorage`. New persistent player state must be added to `PlayerDataModel` and to `PlayerSaveStorage.Capture/Restore`.

## 5. Gotchas found in the code
- No event bus: events are plain `event Action` fields on owners (`AttributeSystem.OnAttributesChanged`, `SkillCaster.OnCast*`, `BuffSystem.OnBuffsChanged`, `PlayerInventory.OnInventoryChanged`, static `SkillTreeManager.OnNodeUnlocked`...). Always unsubscribe in `OnDisable`/`OnDestroy`.
- `Events/`, `Gameplay/`, `Script/DevToolModal/`, `Editor/ProjectMobilityAssistant/` are empty folders.
- Support modifiers and unique passives are discovered by attribute, not switches: `[SupportModifierId(1023)]` / `[UniquePassiveId("Name")]` on the class is the whole registration (`CoreSystem/Utility/AttributedTypeRegistry.cs`). `SupportModifier.Create(id)` assigns `ID` from the attribute; never set `ID` in constructors. `BloodBleedingDOT` is intentionally unregistered (spawned by `BloodBleeding` with caster stats).
- Supports that change *how* a skill executes implement `IPayloadSplitter` (e.g. SpellCascade) or `ICastRepeater` (e.g. EchoSpell) (`Skills/IPayloadSplitter.cs`, `Skills/ICastRepeater.cs`); `SkillCaster` calls them generically. Do not add id checks to `SkillCaster`. Unique passives repeat casts the same way: `ISkillCastRepeater` (`CanRepeat(instance)`, e.g. DoubleSpell; the repeat is a full cast, so linked Echo/Cascade apply to it) and `IBasicAttackRepeater` (e.g. DoubleAttack, read by `Character.BasicAttack`). Repeats weaken the whole hit through `payload.DamageMultiplier` (EchoSpell 0.6, DoubleSpell 0.4), never by scaling `BaseDamage` (that would skip ATK/MATK).
- **All damage goes through `CombatCore`** (`CoreSystem/Combat/`): Gate -> Dispatch by `EffectKind` -> handler Offense (user side) -> Defense (target side) -> Riders (re-enter `Resolve` as procs, max depth `CombatCore.MaxDepth`) -> `OutcomeApplier` (the only place HP changes). `Resolve` is side-effect free; `Execute` = Resolve + Apply. `DamageEffect.Apply` is a one-line adapter; never put math back into effects. Formula edits go in `Combat/Formulas/`, per-kind behaviour in `Combat/Handlers/<Kind>/`. Full design: `Docs/02-Technical/Combat/Combat_Core_Pipeline.md`.
- Unique passive `ref` hooks (OnHit/OnTakeDamage/OnPostHit) still run inside `DamageHandler.Commit` to keep numbers identical; Phase 4 moves them into Offense/Defense modifiers and riders. Proc damage uses `ProcSkillIds` and `UniquePassive.DealProcDamage`; self-inflicted proc damage (bleeds) passes the Gate.
- Fixed Cast Time is reduced only by the Reduce FCT attribute (`FixedCastTimeReduc`, `FixedCastTimeReducPercent`), a Rare Attribute Bonus. Do not add other ways to reduce it.
- **Characters**: never add a Player/Enemy/NPC subclass or put input/AI code on a character. A body is `Character` + data; who drives it is `DefaultController` (Player → `PlayerCore`, Agent → `AgentCore`). All commands go through `character.Control` (`CommandMove`, `CommandCastSkill`, `CommandBasicAttack`, `CommandInterruptCast`); temporary control uses `Control.Claim(holder, ControlLane, duration)`. Monster/villager/boss/merchant are `CharacterTag`s or `AgentProfile` data. Get the player with `PlayerCore.GetPlayer()` (never by tag, Find or `GameData`). Full guide: `Docs/02-Technical/Character/Character_System.md`.
- `Character.RecalculateStats` = derived stats + `PassiveNodes` (tag "Passive"); the legacy global `SkillTreeManager` stats are no longer applied to characters.
- `AdditionalChain` keeps insertion order for entries with equal `Order`.
- UIBuilder: prefer the semantic API (`Column`/`Row`/`Grid`/`Panel`, `Title`/`Heading`/`Label`/`Caption`, `Button(label, onClick, UIVariant)`, `Input`, `Pages`, `Region`, `Foldout`); overloads that take a **style name** first (`"Text"`, `"Button"`, `"Primary Button"`) resolve through `Assets/Prefab/UIElementRegistry.asset`. Colours come from `UITheme` via `UIVariant`, not hard-coded `Color`s.
- **Turning a Figma design into Unity UI**: follow `Docs/02-Technical/UI/Figma_To_Unity_Playbook.md` (export frames, dump node tree, map fonts/sprites, editor builder script with `Place()` at Figma coordinates, render at the Figma position, blend/zoom compare, 0 layout errors).
- Esc menu: `UIManager` raises `OnEscapeUnhandled` when Esc closes no modal; `[Runtime] SystemMenuController` toggles `SystemMenuWindow` (UI/SystemMenu/), which opens `SettingsWindow` (DisplaySetting / AudioSetting / GameSetting) and `SystemConfirmDialog`. Never read Esc elsewhere. Walkthrough: `Docs/02-Technical/UI/System_Menu_Walkthrough.md`.
- Settings are data: pages and options live in `SettingsRegistry` (built-ins in `SettingsCatalog`, keys in `SettingKeys`), values in `SettingsStorage` (versioned JSON) or the owning setting class; systems read them and listen to `SettingsEvents.OnChanged(key)`. Key binding: `KeybindSetting` (call `Attach(inputActions.asset)` after every `new InputSystem_Actions()`; hotbar via `GetHotbarKey`). Walkthrough: `Docs/02-Technical/UI/Settings_Walkthrough.md`.
- Global Modal has a second style: `SetStyle(UIModalStyle.MiniHeader)` (33 px header, `UI_Global_Window_Dark`), parts owned by `UIModalStyleView`; Dark kit prefabs `MH *` in `Prefab/Game Page/Global/UIElement/MiniHeader/` built by **Pale Vertica > UI > Build MiniHeader Window Style** (`Editor/UI/MiniHeaderUIKitGenerator.cs`). Default style unchanged. Walkthrough: `Docs/02-Technical/UI/MiniHeader_Window_Walkthrough.md`.
- Light UI art kit: **Pale Vertica > UI > Build Light UI Kit** (`Editor/UI/LightUIKitGenerator.cs`) builds the art prefab styles (`Button`/`Primary Button` art pair, `Nav Button`, `Chip`, `Foldout Header`/`Section Header`, `Key Value`, `Item Row`, `Attr Cell`, `Level Frame`, `HP/MP/EXP Bar`, `Item Card`, `InputField`) into `Prefab/Game Page/Global/UIElement/Light/`, registers them, sets the light Theme and skins the Global Modal. Art styles use the entry flag **Keep Prefab Look** (variants only recolour the label). Walkthrough: `Docs/02-Technical/UI/Light_UI_Kit_Walkthrough.md`.
- Inspect VITALS (`UI/Inspect/CharacterInspectWindow.cs`) uses the custom element `Status Vitals`, a copy of `StatusModal Window.prefab`'s `Content` made by **Pale Vertica > UI > Build Status Vitals Element** (`Editor/UI/StatusVitalsPrefabBuilder.cs`; never saves StatusModal). Keys `HP/MP/EXP Fill` (`UICustomElement.SetFill`), `HP/MP/EXP Value`, `Base`, `Job`. Change the Status modal, then rebuild, so both stay the same. Walkthrough: `Docs/02-Technical/UI/Status_Vitals_Element_Walkthrough.md`.
- Skill window (`Prefab/Game Page/Character SkillManager Window.prefab`, `UI/Skill Manage Page/`): hand-made Modifier page plus Effect/Basic pages built by **Pale Vertica > UI > Build Skill Manage Pages** (`Editor/UI/SkillManagePrefabBuilder.cs`). Pages are `SkillEffectPageView` / `SkillBasicPageView` listening to `SkillManageWindow.OnSelectedSkillChanged`; Basic values come from `SkillCaster.BuildPayload`. Skills have a `Description` field (Skill.json, ActiveSkill, Workbench). Walkthrough: `Docs/02-Technical/UI/Skill_Manage_Window_Walkthrough.md`.
- After a state change refresh the smallest part: `modal.Refresh(regionId)` / `modal.RefreshPage(pagesId)`; `modal.Refresh()` / `Build` rebuild everything (loses input focus). Layout rules and full API: `Docs/02-Technical/UI/UIBuilder_Guide.md`.
- **Dev-only hooks are tracked** in `Docs/03-Project/Production_Strip_List.md`: when you add a `...Batch` method, builder menu, snapshot hook, render-only public member or test helper, add a row there.
- **Check UI changes visually, do not guess.** With Unity closed run `"D:/Unity/6000.4.8f1/Editor/Unity.exe" -batchmode -projectPath "F:/GameProject/Pale Vertica" -executeMethod CoreSystem.Editor.UI.UISnapshotRenderer.RenderAllBatch -logFile render.log` (no `-nographics`), then Read `Logs/UIDebug/<screen>.png`, `.issues.png` and `.txt` (issues with fix hints + the real layout tree). With Unity open the user can use **Pale Vertica > UI > Render UI Snapshots**, or **F9** / dev tool **Snapshot** in Play mode. `UILayoutRegressionTests` fails on layout errors. Add new builder screens to `UISnapshotRenderer.Run`.
- **MapLab is not game code**: `Assets/ThirdParty/MapLab/` is a standalone map toolkit meant to be sold separately (asmdefs `MapLab`, `MapLab.Editor`, `MapLab.Samples`, `MapLab.Samples.Editor`, `MapLab.Tests.Editor`; menu Tools > MapLab). Never reference `CoreSystem` from it. Its output is a **file**: `MapLabMap` on the map root + Bake writes `<scene>_Walkable.json` (grid bitset + obstacle polygons, format v1) and a PNG mask; consumers read the file, not MapLab types. NavMesh/`NavigationManager` is only a sample consumer (`Samples/Navigation`, no reference to the core). MapLab uses no SpriteShape: roads are `MapLab.Shapes.PathShape`, everything else (plateau / void / ring / box / flat plaza) is `ExtrudedShape` (points = ground footprint = collider; Height raises the top; walls from south-facing footprint edges with UVs along the arc length; Y-sorted in footprint slices via SortingGroups at the character order 6; generated children are DontSave). A shape that is the child of another ExtrudedShape is a tier: it stands on the parent's top, has no collider, and sorts in front of the parent. Icons come from Figma (Preview page, MapLab / Icon Sets, Set 5 Tile) as PNGs in `Editor/Icons/`; `Tools > MapLab > Apply Icons` assigns them. Measure cost with `Tools > MapLab > Performance Report`. The game reads the walkable file through its own `CoreSystem.Pathfinding.WalkableGridManager` (no MapLab types); `SandBox.unity` has one (`Walkable Grid` object). Walkthroughs: `Docs/02-Technical/World/Map_Lab_Walkthrough_TH.md`, `Walkable_Area_Bake_Walkthrough_TH.md`, `Extruded_Shape_Walkthrough_TH.md`, `Path_Shape_Walkthrough_TH.md`, `MapLab_Icons_Walkthrough_TH.md`, `MapLab_Performance_TH.md`, `MapLab_World_Walkthrough_TH.md` (mega chunks of 4096 px: one bake folder `M_x_y` and one PSD each, pan/zoom viewport, floor tiles via `MapLabWorldData` + `MapLabFloor`, presets as `MapLabPreset` assets wrapping a Unity Preset).
- `HotbarManager` is the only place hotbar hotkeys are read; `HotbarSlotView.ExecuteAction()` is the single execution entry.
- `SkillStatusUI` exists but nothing instantiates it. `NPCBrain` is mostly commented out (V2).
- EditMode tests live in `Assets/Script/Editor/Tests/` (compiled into Assembly-CSharp-Editor, namespace `CoreSystem.Tests`): stat pipeline, derived formulas, cast time/cooldown/AOE, `DamageFormula`, the `CombatCore` pipeline (`CombatCoreTests` with `FakeCombatant` + `FixedCombatRandom`), registries, support hooks. Run them in **Window > General > Test Runner > EditMode**, or headless with Unity closed: `"D:/Unity/6000.4.8f1/Editor/Unity.exe" -batchmode -nographics -projectPath "F:/GameProject/Pale Vertica" -runTests -testPlatform EditMode -testResults results.xml -logFile unity.log`. Add a test whenever you touch math. Any formula change must update the matching test deliberately.
- `Data/Tests/DataSystemTest.cs` is a manual smoke test (Inspector context menu "TestSystem"). Gameplay feel still needs Play mode + the K dev tool.

## 6. Documentation workflow
- Hub: `Docs/README.md`. Technical docs go to `Docs/02-Technical/<System>/`, design to `Docs/01-Design/`, superseded docs to `Docs/99-Archive/`.
- Before working on a system, read its doc folder; after changing a system's behaviour, update that doc and the index.
- Language suffix `_TH` / `_EN` for translated variants.
- Anything devs will use again (editor tool, Workbench/pipeline step, template, reusable system) needs `Docs/02-Technical/<System>/<Name>_Walkthrough.md`, linked from `Docs/README.md`: where to open it, inputs, steps in order, expected result, common mistakes. Not done without it (AGENTS.md section 7). Examples: `Items/Costume_System_Walkthrough.md`, `Skills/Skill_Combo_Walkthrough_TH.md`.
