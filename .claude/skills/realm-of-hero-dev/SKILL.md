# Realm of Hero Dev Skill

Unity **6000.4.8f1**, URP 2D, Input System, Addressables, TMP, Newtonsoft JSON, DOTween, Hot Reload (Asset Store). All game code compiles into `Assembly-CSharp` (no asmdefs). Project display name in menus/docs: "Realm of Hero"; folder name: "Pale Vertica".

## 1. Non-negotiable rules (from `AGENTS.md`)
- Reply in **English**, no emoji, concise. Show only modified blocks/methods with clear placement when presenting code to the user.
- **No code comments** unless asked.
- Every C# script uses the five regions in this order: `#region [Variables/Fields]`, `[Properties]`, `[Unity Methods]`, `[Public Methods]`, `[Private Methods]` (bracketed names). Keep them when editing older files that use unbracketed names.
- No god classes. Data in ScriptableObjects/JSON, communication via C# `event Action`.
- UI only **listens** to events. Never poll data in `Update()` when an event exists.
- **Do not change core formulas** (anything in `CoreSystem/Combat/Formulas/`: stat value, derived stats, damage, cast time, cooldown, cost, regen, ASPD, refine, EXP) without explicit user approval. Callers such as `Attribute`, `AttributeSystem`, `SkillInstance`, `SkillCaster`, `Character`, `Equipment` only gather inputs and apply results; never put arithmetic back into them.
- Docs go to `Docs/` only (see section 6). Never create `.md` under `Assets/`.

## 1b. Naming and references (full standard: `Docs/02-Technical/Coding_Standards.md`)
- **Suffix = script type.** `Manager` only for a single global instance per scene/session; `System` for a per-character subsystem; `Player*` for player state; `Controller`, `Director`, `View`/`Window`/`Modal`/`Slot` (UI that only listens), `Database`, `Loader`, `Storage`, `Formula`, `Registry`, `Events`, `Factory`; `Settings`/`Table`/`SO` for ScriptableObject data. No `Helper`/`Utils`. Do not invent new suffixes.
- **Runtime-created objects** (not in a prefab or scene): one `Create()`/`Factory` entry point, GameObject named `[Runtime] X` under the `[Runtime]` root, self-register in `Awake`/clear in `OnDestroy`, expose `IsReady`/`OnReady`, `[DisallowMultipleComponent]` + `[AddComponentMenu("")]`. Nothing uses `DontDestroyOnLoad`; session-long data is a plain C# singleton (`Database`).
- **No runtime Find** (`FindAnyObjectByType`, `FindObjectsByType`, `GameObject.Find`, `FindGameObjectWithTag`) in new game code: use serialized/hierarchy refs, self-registering `Manager`s, `Registry`, or `Events` (core raises, UI listens). Find is fine in `Editor/` and `Reset()`/`OnValidate()`. Existing Find calls are scheduled for removal after the rename phases.
- **Files and namespaces**: one public type per file, file name = type name (grouped enums/structs: `<Area>Types.cs`); namespace = folder path.
- **Renaming**: keep the `.meta` with MonoBehaviour/SO files; add `[MovedFrom]` for `[SerializeReference]` types (`EffectLogic`, `TargetingLogic`, `ActionRider` subclasses); never rename names used as strings (Workbench `SkillConverter`, JSON `EffectType`) without updating them; check `Resources`/Addressables paths before moving folders.
- Legacy names: none left from N1–N5. Multi-type files that had uncommitted user edits at migration time (`UIManager`, `UIBuilderContext`, `UIElementRegistrySO`, `CursorManager`) still hold several types; split them when next touched.

## 3. Data sources of truth
- Gameplay numbers live in JSON: `Assets/Resources/Data/{Item, ItemSet, Faction, Attribute, Skill, SupportSkill, SkillTree, Character, UniquePassive}.json`. Edit them through **Window > Realm of Hero > Game Data Workbench**, not by hand when possible.
- Skill behaviour lives in `ActiveSkill` assets under `Assets/Resources/Skill/ActiveSkill`; `Database.GetSynchronizedSkill(id)` clones the asset and overwrites numbers from `Skill.json`.
- ID ranges and data conventions: `Docs/03-Project/Planning_Guide.md`.
- Save files: `persistentDataPath/Saves/save_slot_{n}.json` via static `SaveStorage`. New persistent player state must be added to `PlayerDataModel` and to `PlayerSaveStorage.Capture/Restore`.

## 5. Gotchas found in the code
- No event bus: events are plain `event Action` fields on owners (`AttributeSystem.OnAttributesChanged`, `SkillCaster.OnCast*`, `BuffSystem.OnBuffsChanged`, `PlayerInventory.OnInventoryChanged`, static `SkillTreeManager.OnNodeUnlocked`...). Always unsubscribe in `OnDisable`/`OnDestroy`.
- `Events/`, `Gameplay/`, `Script/DevToolModal/`, `Editor/ProjectMobilityAssistant/` are empty folders.
- Support modifiers and unique passives are discovered by attribute, not switches: `[SupportModifierId(1023)]` / `[UniquePassiveId("Name")]` on the class is the whole registration (`CoreSystem/Utility/AttributedTypeRegistry.cs`). `SupportModifier.Create(id)` assigns `ID` from the attribute; never set `ID` in constructors. `BloodBleedingDOT` is intentionally unregistered (spawned by `BloodBleeding` with caster stats).
- Supports that change *how* a skill executes implement `IPayloadSplitter` (e.g. SpellCascade) or `ICastRepeater` (e.g. EchoSpell) (`Skills/IPayloadSplitter.cs`, `Skills/ICastRepeater.cs`); `SkillCaster` calls them generically. Do not add id checks to `SkillCaster`.
- **All damage goes through `CombatCore`** (`CoreSystem/Combat/`): Gate -> Dispatch by `EffectKind` -> handler Offense (user side) -> Defense (target side) -> Riders (re-enter `Resolve` as procs, max depth `CombatCore.MaxDepth`) -> `OutcomeApplier` (the only place HP changes). `Resolve` is side-effect free; `Execute` = Resolve + Apply. `DamageEffect.Apply` is a one-line adapter; never put math back into effects. Formula edits go in `Combat/Formulas/`, per-kind behaviour in `Combat/Handlers/<Kind>/`. Full design: `Docs/02-Technical/Combat/Combat_Core_Pipeline.md`.
- Unique passive `ref` hooks (OnHit/OnTakeDamage/OnPostHit) still run inside `DamageHandler.Commit` to keep numbers identical; Phase 4 moves them into Offense/Defense modifiers and riders. Proc damage uses `ProcSkillIds` and `UniquePassive.DealProcDamage`; self-inflicted proc damage (bleeds) passes the Gate.
- `AGENTS.md` says Fixed Cast Time is immutable, but `SkillInstance` currently reduces FCT via `FixedCastTimeReduc` and FCT%. Flag this to the user instead of silently "fixing" it.
- **Characters**: never add a Player/Enemy/NPC subclass or put input/AI code on a character. A body is `Character` + data; who drives it is `DefaultController` (Player → `PlayerCore`, Agent → `AgentCore`). All commands go through `character.Control` (`CommandMove`, `CommandCastSkill`, `CommandBasicAttack`, `CommandInterruptCast`); temporary control uses `Control.Claim(holder, ControlLane, duration)`. Monster/villager/boss/merchant are `CharacterTag`s or `AgentProfile` data. Get the player with `PlayerCore.GetPlayer()` (never by tag, Find or `GameData`). Full guide: `Docs/02-Technical/Character/Character_System.md`.
- `Character.RecalculateStats` = derived stats + `PassiveNodes` (tag "Passive"); the legacy global `SkillTreeManager` stats are no longer applied to characters.
- `AdditionalChain` keeps insertion order for entries with equal `Order`.
- `UIBuilderContext` element methods take a **style name** first (`"Div"`, `"Text"`, `"Button"`, `"Primary Button"`), resolved through `Assets/Prefab/UIElementRegistry.asset`; not an element id.
- UIBuilder is imperative: rebuild with `modal.Build(BuildUI)` when state changes.
- `HotbarManager` is the only place hotbar hotkeys are read; `HotbarSlotView.ExecuteAction()` is the single execution entry.
- `SkillStatusUI` exists but nothing instantiates it. `NPCBrain` is mostly commented out (V2).
- EditMode tests live in `Assets/Script/Editor/Tests/` (compiled into Assembly-CSharp-Editor, namespace `CoreSystem.Tests`): stat pipeline, derived formulas, cast time/cooldown/AOE, `DamageFormula`, the `CombatCore` pipeline (`CombatCoreTests` with `FakeCombatant` + `FixedCombatRandom`), registries, support hooks. Run them in **Window > General > Test Runner > EditMode**, or headless with Unity closed: `"D:/Unity/6000.4.8f1/Editor/Unity.exe" -batchmode -nographics -projectPath "F:/GameProject/Pale Vertica" -runTests -testPlatform EditMode -testResults results.xml -logFile unity.log`. Add a test whenever you touch math. Any formula change must update the matching test deliberately.
- `Data/Tests/DataSystemTest.cs` is a manual smoke test (Inspector context menu "TestSystem"). Gameplay feel still needs Play mode + the K dev tool.

## 5b. Unity Editor access (Unity-MCP)
- Use the Unity-MCP server `ai-game-developer` (`http://localhost:28971`, configured in `.mcp.json` and `UserSettings/AI-Game-Developer-Config.json`) for anything that touches the live Editor: `rql-query` / `rql-schema` to inspect scenes, prefabs, assets and console logs; `rql-mutate` for undoable scene/prefab edits; `tests-run` for EditMode/PlayMode tests; `screenshot-isolated`; `script-execute` for one-off editor C#. RQL syntax: the generated `unity-rql` skill.
- Prefer it over hand-editing `.unity`/`.prefab` YAML or running batch-mode tests, which both need the Editor closed. `tests-run` aborts when an open scene is dirty.
- If the server does not answer (Editor closed), fall back to closed-Editor YAML edits and the batch-mode test command in section 5.
