# Realm of Hero Dev Skill

Unity **6000.4.8f1**, URP 2D, Input System, Addressables, TMP, Newtonsoft JSON, DOTween, Hot Reload (Asset Store). All game code compiles into `Assembly-CSharp` (no asmdefs). Project display name in menus/docs: "Realm of Hero"; folder name: "Pale Vertica".

## 1. Non-negotiable rules (from `AGENTS.md`)
- Reply in **English**, no emoji, concise. Show only modified blocks/methods with clear placement when presenting code to the user.
- **No code comments** unless asked.
- Every C# script uses the five regions in this order: `#region [Variables/Fields]`, `[Properties]`, `[Unity Methods]`, `[Public Methods]`, `[Private Methods]` (bracketed names). Keep them when editing older files that use unbracketed names.
- No god classes. Data in ScriptableObjects/JSON, communication via C# `event Action`.
- UI only **listens** to events. Never poll data in `Update()` when an event exists.
- **Do not change core stat formulas** (`AttributeSystem.InnerUpdateDerivedAttributes`, `Attribute.Recalculate`, `DamageEffect`, `SkillInstance` cast-time math) without explicit user approval.
- Docs go to `Docs/` only (see section 6). Never create `.md` under `Assets/`.

## 3. Data sources of truth
- Gameplay numbers live in JSON: `Assets/Resources/Data/{Item, ItemSet, Faction, Attribute, Skill, SupportSkill, SkillTree, Character, UniquePassive}.json`. Edit them through **Window > Realm of Hero > Game Data Workbench**, not by hand when possible.
- Skill behaviour lives in `ActiveSkill` assets under `Assets/Resources/Skill/ActiveSkill`; `Database.GetSynchronizedSkill(id)` clones the asset and overwrites numbers from `Skill.json`.
- ID ranges and data conventions: `Docs/03-Project/Planning_Guide.md`.
- Save files: `persistentDataPath/Saves/save_slot_{n}.json` via static `SaveManager`. New persistent player state must be added to `PlayerDataModel` and to `PlayerCharacter.SaveData/LoadData`.

## 5. Gotchas found in the code
- No event bus: events are plain `event Action` fields on owners (`AttributeSystem.OnAttributesChanged`, `SkillCaster.OnCast*`, `TemporaryBuffManager.OnBuffsChanged`, `PlayerInventory.OnInventoryChanged`, static `SkillTreeManager.OnNodeUnlocked`...). Always unsubscribe in `OnDisable`/`OnDestroy`.
- `Events/`, `Gameplay/`, `Script/DevToolModal/`, `Editor/ProjectMobilityAssistant/` are empty folders.
- Factory switches must be updated when adding types: `UniquePassiveManager.CreatePassive(string)` and `SupportModifier.Create(id)` (ids 1001-1022). `BloodBleedingDOT` currently has no factory case.
- Support ids 1021 (EchoSpell) and 1022 (SpellCascade) are special-cased inside `SkillCaster.ExecutePipeline`.
- `AGENTS.md` says Fixed Cast Time is immutable, but `SkillInstance` currently reduces FCT via `FixedCastTimeReduc` and FCT%. Flag this to the user instead of silently "fixing" it.
- `PlayerCharacter.RecalculateStats` removes "Passive"-tagged Additional entries added by `ApplyPassiveStats` and re-adds from `PassiveNodes` - two sources fight over the same tag.
- `UIBuilderContext` element methods take a **style name** first (`"Div"`, `"Text"`, `"Button"`, `"Primary Button"`), resolved through `Assets/Prefab/UIElementRegistry.asset`; not an element id.
- UIBuilder is imperative: rebuild with `modal.Build(BuildUI)` when state changes.
- `HotbarManager` is the only place hotbar hotkeys are read; `HotbarSlotUI.ExecuteAction()` is the single execution entry.
- `SkillStatusUI` exists but nothing instantiates it. `NPCBrain` is mostly commented out (V2).
- No automated tests. `Data/Tests/DataSystemTest.cs` runs via Inspector context menu "TestSystem". Verify changes by compiling in Unity and using the K dev tool.
